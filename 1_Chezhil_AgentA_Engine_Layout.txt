SECTION 1: PROJECT OVERVIEW
==========================================================================

PROJECT: Dead-Hand Console
Hackathon: ACM MarketSphere 2026, Round 2 (build round), Track 3: Flash-Crash Simulation.
Client (fictional case): MochaTrade, a perpetual-futures trading app. Users are in India; its
three founders are in San Francisco, asleep during India's peak trading hours.

OUR ROUND 1 THESIS ("Dead-Hand Protocol"):
Three people cannot out-react a flash crash, so every decision is made in advance and the
system executes it without waiting for humans. In the first 60 minutes, humans make
exactly ONE call: confirming the auto-queued makegood (compensation) list.

KEY RULES FROM ROUND 1 (the app must enforce these exactly):
- Price = median of 3 independent reference feeds. If feeds disagree, liquidations pause.
- Asymmetric circuit breaker: halt NEW LEVERAGED OPENS only. Top-up, reduce, close and
  withdraw always stay open.
- Deviation Doctrine: "We pay when our price was wrong. We never pay because the market was."
  deviation% = |our execution price - reference median| / reference median x 100.
  If deviation > published band (default 2.00%), the user gets an automatic makegood.
  Makegood restores the position; it never pays a profit.
- The band is published before launch and CANNOT change during a crisis.
- Integrity Reserve: 10% of gross trading fees, in a segregated account, balance public.
  If ever short, pay pro-rata and disclose.
- One fractional on-call responder in IST covers the sleep gap.

TIMELINE THE APP SIMULATES (sim time from crash start):
T+00:00  Watchdog flags feed divergence (DETECT)
T+00:01  IST responder paged
T+00:02  New leveraged opens halted; exits stay live (CONTAIN)
T+00:04  Responder acknowledges
T+00:05  Status page live + push to every open position
T+00:15  Deviation test runs on every liquidation (DECIDE)
T+00:30  Makegoods queued; "Confirm makegoods" button appears (the one human call)
T+01:00  Public post: feed data, verdict, what we owe (DISCLOSE)

WHAT THE APP IS:
A single-page web app with no backend and no login. All data is simulated. The user picks
a scenario, presses Start, and watches the protocol run the incident automatically in
fast-forward. The only thing the user clicks during the crash is "Confirm makegoods".
It must feel calm, not chaotic: it is an autopilot console, not a wall of alarms.

THREE SCENARIOS:
1. "System fault": Feed A glitches; our execution price follows the bad feed.
   Many liquidations deviate > 2% -> makegoods owed. (Matches Round 1 Case A:
   median $402.10, ours $388.40, deviation 3.41%, owed $13.70 per unit.)
2. "Real market move": All three feeds fall together; our price tracks them.
   Deviations < 2% -> no makegoods, data still published. (Case B: median $351.00,
   ours $349.60, deviation 0.40%.)
3. "Historical replay": Price shape approximating a publicly documented crypto flash crash,
   labelled clearly in the UI as "approximate reconstruction".

VISUAL STYLE (match our Round 1 deck):
Dark navy background (#0A1020), panel surface (#0F1A30), cyan primary (#22C3D6),
orange for alerts/warnings (#FF8C42), green for good/resolved (#3DD68C), muted text (#8A97B0).
Rounded panels, clean sans-serif, numbers in tabular figures. Calm, not flashy.
Desktop-first (demoed on a laptop/projector at 1440px wide), but must not break at 1280px.

TECH STACK (fixed, do not change):
Vite + React + TypeScript, Tailwind CSS, Zustand for state, Recharts for charts.
No backend, no router needed (modals/drawers for secondary views).

Agent B (Kaustubh, Comms Lead): message templates, comms feed, social panel, public/user views, report.

TYPES (src/core/types.ts)
type ScenarioId = 'system_fault' | 'market_move' | 'historical_replay';
type Phase = 'setup' | 'running' | 'paused' | 'ended';
type Stage = 'detect' | 'contain' | 'decide' | 'disclose';

interface PricePoint { t: number; feedA: number; feedB: number; feedC: number;
  median: number; ours: number; }                       // t = sim seconds since crash
interface SignalPoint { t: number; liquidationsPerMin: number; ticketsPerMin: number;
  socialMentionsPerMin: number; }
interface OrderTypes { newLeverage: boolean; topUp: boolean; reduce: boolean;
  close: boolean; withdraw: boolean; }                   // true = open
interface Liquidation { id: string; t: number; userId: string; userName: string;
  side: 'long' | 'short'; qty: number; referenceMedian: number; executionPrice: number;
  deviationPct: number | null; verdict: 'pending' | 'makegood' | 'no_makegood';
  amountOwed: number; status: 'untested' | 'tested' | 'queued' | 'confirmed' | 'paid'; }
type Channel = 'status_page' | 'push' | 'x_post' | 'email';
interface CommsMessage { id: string; templateId: string; t: number; channel: Channel;
  title: string; body: string; status: 'scheduled' | 'sent'; }
interface LogEntry { id: string; t: number; actor: 'system' | 'responder' | 'human';
  stage: Stage; text: string; }
interface Responder { status: 'idle' | 'paged' | 'acknowledged' | 'on_it';
  pagedAt?: number; ackAt?: number; name: string; }

STORE (src/core/store.ts, Zustand), state:
phase, scenario, speed (1 | 20 | 60), simTime (seconds, 0-3600), stage,
bandPct (default 2.0), bandLocked, feedStatus ('agree' | 'diverging' | 'liquidations_paused'),
prices: PricePoint[], signals: SignalPoint[], orderTypes, liquidations: Liquidation[],
comms: CommsMessage[], log: LogEntry[], responder,
reserveStart (default 250000), reserveBalance, humanCallsUsed (0 or 1),
makegoodButtonVisible, selectedUserId (string | null), activeDrawer
('none' | 'comparison' | 'public_page' | 'user' | 'report').

Actions: setScenario, setBand (ignored if bandLocked), setSpeed, start (locks band),
pause, resume, reset, confirmMakegoods (humanCallsUsed=1, queued->confirmed->paid,
reserve drops, logs a 'human' entry), selectUser(id), openDrawer(name), closeDrawer().

ENGINE (src/core/engine.ts), owned by Agent A:
Ticks every 250ms of real time and advances simTime by 0.25 x speed.
Generates prices/signals from the scenario, fires timeline events at fixed times, creates
liquidations, calls runDeviationTest() (from Agent C) at T+15:00 and on every new
liquidation afterwards, and schedules comms from TEMPLATES (from Agent B) by templateId.
Social mentions rise steeply from T+5 min, then flatten after the status-page message is
sent (the engine applies a damping factor once a 'status_page' message is 'sent').
